# CAP Index Toolkit 1.2.0 Change Brief: Tool Setup Form

Oct 15, 2026 · @Grant

## Purpose and constraints

Version 1.2.0 replaces each tool's chain of prompts with one setup window: pick the data, map fields from dropdowns, set options, then Run. Analytical calculations do not change.

Baseline source: the 1.1.0 release. Start only after 1.1.0 builds clean with no `FAILED.txt`.

Rules for the implementer:

- Change entry paths and prompts only. Do not change any calculation, output layout or report refresh behavior.
- Keep every existing public procedure and its programmatic signature. Automated tests call tools with a `source` range and header names; that path must keep working without any form.
- Keep ownership notices and version-specific ribbon callback names.
- Match the existing message tone and the About CAP Index window's branding. Do not use em dashes in user-facing text.
- Where this brief names a module, procedure or cell, confirm it against the current source before editing.

## Current input flow and its problems

Most analysis tools open 6 to 11 separate dialogs before any output appears, and one typo in a typed header name fails the run at the end.

| Tool | Dialogs before output | Where the prompts live |
| --- | --- | --- |
| Trends, Period Comparison, Crime Profile | 11 (range, confirm, 4 fields, crime list, crime pick, measure, start date, end date) | `modReportInput.ReadReportInput` |
| Hot Streets | 9 (range, confirm, 7 fields) | `modTimeReports.BuildTimeReport` |
| Crime Concentration | 8 (range, confirm, 6 fields) | `modConcentration.BuildConcentrationReport` |
| Repeat Locations | 8 (range, confirm, 6 fields) | `modTimeReports.BuildTimeReport` |
| Randomize Block Addresses | 7 (range, confirm, 4 fields, seed) | `modSimpleOutputs.BuildHundredBlocks` |
| Temporal Heat Map | 7 (input mode, range, confirm, 4 fields) | `modTimeReports.BuildTimeReport` |
| Census Geocoder | 6 (range, confirm, 4 fields) | `modSimpleOutputs.GeocodeCensus` |
| NIBRS Crosswalk | 5 (range, confirm, 2 fields, federal yes/no) | `modNIBRS.PrepareNIBRSCrosswalk` |

Counts exclude the closing summary message and the 1.1.0 expansion dialog. Confirm Single Site, Year over Year, Seasonality and Dataset Check against `modSingleSite`, `modCalendarAnalysis` and `modDatasetCheck`; they were not read for this brief.

Problems the form must solve:

1. **Typed header names.** `AskColumn` requires the exact header text. A typo surfaces as "Missing source header" only after the user has answered every earlier prompt.
2. **Remembered fields saved under the wrong role.** `modUsability.FieldRole` guesses the role by scanning the prompt text for keywords, in a fixed order. Prompts that mention another role's keyword are misfiled:
   - "Optional City to prevent combining identical addresses/blocks across cities" (Repeat Locations, Hot Streets) and "Optional City to distinguish identical block addresses" (Randomize) save the City header as ADDRESS.
   - "Optional ZIP when City and State are available" (Census Geocoder) saves the ZIP header as CITY.
   - The next run then pre-fills the Address prompt with the City header, and the City prompt with the ZIP header.
3. **Crime filter by number.** Reporting tools list crime types in a message box, then ask for a number. When the list exceeds 900 characters, the user must type the exact internal label, including the "Type: " prefix.
4. **Abstract choices.** Count measure is entered as 1 or 2. The heat map asks for an input mode from 1 to 4 before the user has selected any data.
5. **No way back.** Cancelling or mistyping late in the chain discards every earlier answer.

## Design: one shared setup form

One form, `frmCAPSetup`, serves every migrated tool. A short definition per tool (Section 4) decides which fields and options it shows. All choices are visible on one screen; nothing runs until the user clicks Run.

Use grouped regions on a single page, not tabs. Tabs suit the About window, which is browsed. A setup screen should show every choice at once before Run.

| Region | Controls | Behavior |
| --- | --- | --- |
| Header | CAP logo, tool name, one-sentence description of what the tool needs | Same branding and Calibri styling as `frmCAPAbout` |
| Data | Range address (read-only), "Select range" button, row and field count, Analysis Scope line | "Select range" hides the form, calls `Application.InputBox` (Type 8), then shows the form again. Counts reflect the range the tool will actually process, after `FullWorkingSource` expansion for geography tools. Pre-fill with the current selection when it is a valid range. |
| Fields | Up to 10 rows: role label, header dropdown, required marker, one-line help | Dropdowns list the data's header row. Optional roles include "(none)" as the first item. Changing the range reloads headers and keeps any selection whose header still exists. |
| Options | Up to 6 rows: label plus a dropdown or text box | Tool-specific settings such as seed, count measure, crime filter, dates, heat map time input and federal/tribal applicability. |
| Status | One line of text above the buttons | Shows the first blocking problem in plain words, such as "Choose a Crime Type field." No message boxes during setup. |
| Buttons | Run, Cancel, Tool Guide | Run is disabled until the Status line is clear. Cancel closes with no changes. Tool Guide opens the existing guide. |

Form rules:

- **Modal.** Show with `vbModal`. Do not use the RefEdit control; it is unreliable inside add-ins.
- **Fixed slots.** Build 10 field rows and 6 option rows at build time and hide unused ones at run time. This avoids wiring events for controls created at run time.
- **Pre-fill order** for each field: the remembered header for that role if it exists in the data; otherwise a header matching one of the role's suggested names (case-insensitive); otherwise blank for required roles and "(none)" for optional roles.
- **Duplicate check.** One header cannot fill two different roles. Show it on the Status line.
- **Crime filter.** For tools with a crime filter, fill the dropdown with "All crime types" plus the distinct crime values from the chosen Crime Type field. Show plain values; convert to the internal "Type: " label behind the scenes.
- **Dates.** When a Date field is chosen, pre-fill Start and End with the observed minimum and maximum dates and show the observed span beside them.
- **Census notice.** The Census Geocoder form shows a fixed line: "Address components and request IDs are sent to the US Census Bureau."
- **Fits small screens.** The form must fit within 1366 by 768 pixels at 100% scaling.

## Tool definitions

Each migrated tool is described by data, not by its own form: a title, a description, its field roles and its options. Roles use fixed keys so remembered mappings are filed correctly.

**Role keys.** Mappings are saved under these keys. Section 6 explains which mappings saved by earlier versions carry over.

| Role key | Label shown | Suggested headers |
| --- | --- | --- |
| ADDRESS | Address | Address, Full Address, CAP\_SyntheticAddress |
| CITY | City | City |
| STATE | State | State |
| ZIP | ZIP | ZIP, Zip, ZipCode, Postal Code |
| HUNDRED-BLOCK | Hundred Block | CAP\_HundredBlock |
| LOCATION | Location (reports) | CAP\_HundredBlock, Address |
| LOCATION LABEL | Location label | none |
| CRIME | Crime Type | CrimeType, Crime Type, Offense |
| INCIDENTID | Incident ID | IncidentID, Incident ID |
| DATE | Date | Date, OccurredAt |
| TIME | Time | Time |
| HOUR | Hour (0-23) | Hour (0-23), Hour from Time (0-23) |
| DAY OF WEEK | Day of Week | Day of Week |
| AGENCY | Agency | Agency |

ZIP and LOCATION are new keys. Previously both were misfiled under other roles.

**Tools.**

| Tool | Required fields | Optional fields | Options |
| --- | --- | --- | --- |
| Hundred-Block Builder | Address | none | none |
| Randomize Block Addresses | Address | Incident ID, City, State | Seed, default 20261013 |
| Census Geocoder | Address, plus City and State or ZIP | City, State, ZIP | none; shows the Census notice |
| Crime Concentration | Hundred Block, Crime Type | City, State, Location label, Incident ID | none |
| Temporal Heat Map | Crime Type, plus the fields the Time input needs | Incident ID | Time input |
| Repeat Locations | Address, Crime Type | Incident ID, Location label, City, State | none |
| Hot Streets | Hundred Block, Crime Type, Date | Incident ID, Location label, City, State | none |
| Trends, Period Comparison, Crime Profile | Date, Crime Type | Incident ID, Location | Crime filter, Count measure, Start date, End date |
| NIBRS Crosswalk | Crime Type | Agency | Federal/tribal reporting, default No |

**Option details.**

- **Time input** (heat map) replaces the numbered mode prompt. Choices and the fields each makes required: "Date or timestamp" (Date; Hour optional), "Date plus separate Time" (Date, Time; the current default), "Day of Week plus Hour" (Day of Week, Hour), "Day of Week plus Time" (Day of Week, Time). Fields not used by the choice are hidden.
- **Count measure** offers "Unique incidents" only when Incident ID is mapped; otherwise it is fixed to "Source records."
- **Report-sheet controls** such as Hot Streets intervals and repeat gap windows stay on the report sheet. They are not setup options.

Confirm before building: Single Site, Year over Year, Seasonality, Dataset Check and Duplicate / Case Review. Read their current prompts and add a definition for each in the same format. Confirm whether Period Comparison asks for a second date range and add those options if so.

## Implementation steps

The form becomes a new front door to each tool's existing programmatic path. Tools already accept a `source` range and header names; the form collects those and calls the same procedures.

1. **New module `modToolSpecs`.** Add `Public Function ToolSpec(ByVal toolId As String) As Object` returning a Scripting.Dictionary with title, description, roles (key, label, required flag, help text, suggested headers) and options (key, label, type, choices, default). One `Case` per tool in Section 4. Add `Public Function ToolSpecIds() As Variant` listing every defined tool for tests.
2. **New form `frmCAPSetup`, built at build time.** Add `DesignCAPSetup` beside `DesignCAPAbout` in `modAbout`, following the same designer pattern, and call it from `tools/Build-Addin.ps1` where the About form is designed. Create the regions in Section 3 with 10 field slots and 6 option slots. Name controls predictably, such as `cboField1` to `cboField10` and `lblField1` to `lblField10`.
3. **New module `modSetup`.**
   - `Public Function RunSetup(ByVal toolId As String) As Object` shows the form and returns a dictionary with `Source` (Range), one entry per role key (header text, or empty for none) and one entry per option. It returns Nothing on Cancel.
   - `Public Function SetupProblem(ByVal spec As Object, ByVal headers As Variant, ByVal selections As Object, ByVal source As Range) As String` returns the first blocking problem, or an empty string. The form calls it on every change; tests call it directly.
   - `Public Function SuggestHeader(ByVal role As Object, ByVal headers As Variant, ByVal wb As Workbook) As String` applies the pre-fill order from Section 3.
4. **Wire each tool's interactive branch.** In each tool's ribbon entry procedure, replace the `PickSource` and `AskColumn` chain with `RunSetup`, then call the existing procedure with `source` and header names from the result. Pass an empty string for every optional role the user left as "(none)". Several procedures default optional headers to names like "IncidentID"; an omitted argument would silently map them.
5. **Error display.** When `source` is supplied, tools raise errors instead of showing them. The new interactive branch catches those errors and shows them in one message box titled with the tool name.
6. **Remembered fields.** On Run, save each mapped role with `RememberField` using the explicit role key. Change `SavedField` and `RememberField` to accept a role key directly. Add an optional explicit role key argument to `AskColumn` and pass it from every caller that still uses `AskColumn`. Keep `FieldRole` only as a fallback when no key is passed.
7. **Leave unchanged.** Timestamp Fields and Hour from Time (single-column tools), report-sheet controls, Refresh Report, Reset to All, exports and every ribbon callback name.

## How the form works with existing behavior

The form changes how inputs are collected, not what the tools do with them.

- **Analysis Scope.** The Data region shows the workbook's current scope (All Rows or Visible Rows Only). Analysis tools keep applying it through `ScopedValues`. Preparation tools (Hundred-Block Builder, Randomize, Census Geocoder) say "Processes all rows" instead, matching current behavior.
- **1.1.0 expansion dialog.** Form-launched runs pass `source`, so `ConfirmWorkingSource` is skipped by design. The Data region replaces it: for geography tools it shows the range and row count after `FullWorkingSource` expansion, before Run. Keep `ConfirmWorkingSource` and `ExpansionSummary` in place; the form can reuse `ExpansionSummary` text for its count line.
- **Selection confirmation.** The `PickSource` confirmation box is not shown for form-launched runs; the Data region carries the same workbook, sheet, row and field details. Keep `PickSource` for any tool not yet migrated.
- **Remembered mappings.** Save new mappings as custom properties named "CAP Role " plus the role key. Read the legacy "CAP Field " properties only as a fallback, and only for roles the old `FieldRole` never misfiled: STATE, CRIME, INCIDENTID, DATE, TIME, HOUR, DAY OF WEEK, LATITUDE, LONGITUDE and LOCATION LABEL. Ignore legacy ADDRESS, CITY and HUNDRED-BLOCK values; prompts for other roles were saved under those keys. Users pick those fields once and the corrected mapping is saved.
- **Automated tests.** Every existing test passes `source` and header names directly and never sees the form. All existing assertions must pass unchanged.
- **Report sheets.** Blue control cells, Refresh Report and Reset to All are unchanged. Reports built by 1.1.0 refresh normally.

## Out of scope for 1.2.0

Do not implement these in this release.

- A docked task pane or modeless window. That needs a COM or VSTO add-in, not VBA.
- Setup forms for Timestamp Fields, Hour from Time, exports, Refresh Report and Reset to All.
- Any change to calculations, report layouts or report-sheet controls.
- Street suffix and directional standardization, and default-time detection (still deferred from 1.1.0).
- Support for Excel for Mac or Excel for the web.

## Tests, manual acceptance and version

Release as 1.2.0 after a clean build plus a manual pass through every migrated tool. The build cannot click through a form, so the manual pass is required.

**Automated tests** (new module `modSetupTests`, registered in the build):

- Every ID from `ToolSpecIds` returns a spec with a title, at least one required role, unique role keys and valid option defaults.
- `SetupProblem` returns a message for: no range, a missing required field, one header in two roles, Census with Address only, Unique incidents without Incident ID, and Start date after End date. It returns an empty string for a complete Crime Concentration setup on the existing fixture.
- `SuggestHeader` prefers a "CAP Role " mapping, falls back to suggested names, and ignores a legacy ADDRESS value equal to the City header.
- A form check like `CheckCAPAbout`: `frmCAPSetup` loads with 10 field slots, 6 option slots, and Run, Cancel and Tool Guide buttons.
- All 1.1.0 assertions pass unchanged.

**Manual acceptance** on the synthetic fixture:

- [ ] Each migrated tool opens one setup window and produces the same output as 1.1.0 for the same inputs
- [ ] Cancel at any point creates no sheet
- [ ] Run stays disabled until every required field is filled; the Status line names what is missing
- [ ] A second run pre-fills the fields chosen in the first run
- [ ] A geography tool shows the expanded row count before Run
- [ ] The heat map hides fields its Time input does not use
- [ ] The crime filter lists plain crime values and the report shows the matching selection
- [ ] The form fits on a 1366 by 768 screen

**Version and documentation.** Set `CAP_VERSION` to "1.2.0". Add a README paragraph and `docs/RELEASE-1.2.0.md`. Update the About form's What's New tab, and rewrite the selection steps in `modToolGuide` to describe the setup window instead of the prompt sequence.

## Approved changes and implementation outcome (October 15, 2026)

### Approved scope changes

- Preserve 1.1.0 selected-data behavior. References above to expansion dialogs, ConfirmWorkingSource and ExpansionSummary are obsolete and are not implemented.
- Include Single Site, Year over Year, Seasonality, Dataset Check and Duplicate / Case Review for a total of sixteen setup tools.
- Dataset Check has no required field mapping; all fields remain optional.
- Period Comparison includes A start/end and B start/end, with A ending before B starts.
- Help stays inside the setup window and creates no worksheet.
- Keep the window's inputs after execution errors; close on successful completion or Cancel. Failed operations may retain completed outputs under existing behavior.
- Preserve old programmatic calls by adding optional explicit role keys rather than replacing public signatures. Report controls and ribbon callback names remain unchanged.
