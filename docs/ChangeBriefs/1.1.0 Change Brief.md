# CAP Index Toolkit 1.1.0 Change Brief

Oct 15, 2026 · @Grant

## Purpose and constraints

Version 1.1.0 makes four targeted changes to the 1.0.0 baseline (build 20261014-143016). Three fix labeling or behavior; only Change 2 alters an analytical output, and only its descriptive label.

Baseline source: `src/vba` and `src/ribbon`, which match `build/20261014-143016/imports`.

Rules for the implementer:

- Change only what this brief specifies. Do not refactor, rename or reformat untouched code.
- Keep ownership notices, version-specific ribbon callback names and existing public signatures. New parameters are Optional and go at the end of the list.
- Match the existing message tone. Do not use em dashes in any user-facing text.
- Every change ships with new assertions in the named test module. All existing assertions must still pass.
- Where this brief names a line number or cell, confirm it against the current source before editing.

## Change 1: Crime Concentration labeling

The headline must state that percentages describe only blocks with recorded crime. The calculation does not change.

**Why.** A crime file contains no zero-crime blocks, so the denominator is populated blocks only. Published concentration estimates (Weisburd, 2015) include zero-crime street segments. The current headline sits beside that citation and invites a direct comparison that the data cannot support. Including zeros raises the crime share captured by any top percentage, so this report's figures will read lower than published ones.

**Where.** `modConcentration`.

1. In `RefreshConcentration`, rewrite the cell A25 sentence to open with the denominator. Target wording: "Among \[n\] hundred blocks with at least one eligible event, the top \[B18\] blocks (actual \[C18\]) account for \[D18\] of eligible \[measure\]." Keep the existing number formats.
2. In `BuildConcentrationReport`, replace the A32 note with: "Research context: Weisburd (2015), Law of Crime Concentration. https://doi.org/10.1111/1745-9125.12070. Published estimates include places with zero crime. This report counts only blocks with recorded crime, so its percentages are not directly comparable and will read lower."
3. Leave B6, the chart titles and the axis titles unchanged; they already say populated blocks.
4. Update the Crime Concentration entry in `modToolGuide` and the README tool table with the same caveat in one sentence.

**Older reports.** Refresh rewrites A25, so it updates. The A32 note in reports built before 1.1.0 keeps its old text until rebuilt. That is acceptable.

**Tests** (`modConcentrationTests`). After a refresh on the existing 5%/65% fixture, A25 begins with "Among" and contains the populated block count. A newly built report's A32 contains "zero crime".

## Change 2: Hot Streets minimum volume

Rise, fall and emerging labels require at least 10 events across the early and late comparison windows. Below that, the block is labeled "Low volume; no trend label."

**Why.** `StreetProfile` compares mean daily rates in the first and last thirds of complete bins. With small counts the ratio is noise: 1 early event and 2 late events is +100% and currently reads "Rising (descriptive)."

**Where.** `modTimeAnalysis`.

1. Add `Public Const HOT_STREETS_MIN_EVENTS As Long = 10`.
2. Add `Optional ByVal minEvents As Long = HOT_STREETS_MIN_EVENTS` as the last parameter of `StreetProfile`.
3. Inside the existing loop over complete bins, also sum the raw counts (not rates) for the early window and the late window, using the same `binWidth` boundaries already used for `early` and `late`.
4. After the loop and before any labeling, if early count plus late count is below `minEvents`, return label "Low volume; no trend label", keep the early and late rates, set relative change to "Below minimum events", and skip every other label (including "Emerging from zero baseline").
5. Keep the existing "Insufficient complete intervals" check first; it still applies when fewer than 3 complete bins exist.
6. In `RenderHotStreets`, append to the A17 note: "Rise/fall labels require at least 10 events across the early and late windows."
7. No change is needed in `CreateStreetProfileChart`; the new label becomes its own series.

**Tests** (Hot Streets test module, `modTimeTests`). Call `StreetProfile` directly with synthetic bins:

| Early events | Late events | Threshold | Expected label |
| --- | --- | --- | --- |
| 1 | 2 | 25% | Low volume; no trend label |
| 0 | 3 | 25% | Low volume; no trend label |
| 0 | 12 | 25% | Emerging from zero baseline |
| 6 | 12 | 25% | Rising (descriptive) |
| 12 | 6 | 25% | Falling (descriptive) |

Use equal-length bins so rates and counts move together.

## Change 3: Confirm the expanded selection

When a geography tool expands the user's selection, show the real row and field counts and let the user cancel before any output is created.

**Why.** `PickSource` confirms the rows the user selected. The geography tools then call `FullWorkingSource`, which expands to the whole Excel Table or current region. A user can confirm 500 rows and have 12,000 processed, with no notice.

**Decision.** Keep full-dataset expansion, which the README describes as intended, and make it visible. Open question for Grant: if partial-row selections should be honored instead, expand columns only and skip this change.

**Where.** `modSimpleOutputs`.

1. Add `Public Function ExpansionSummary(ByVal selected As Range, ByVal expanded As Range) As String`. Return an empty string when both ranges have the same address on the same sheet. Otherwise return: "Your selection (\[x\] data rows, \[y\] fields) was expanded to the full dataset at \[address\] (\[X\] data rows, \[Y\] fields). Geography tools process every row in the dataset. Continue?"
2. Add `Public Function ConfirmWorkingSource(ByVal selected As Range, ByVal expanded As Range) As Boolean`. It returns True when the summary is empty; otherwise it shows the summary in an OK/Cancel box titled "CAP Index | Confirm dataset" and returns True only on OK.
3. In `BuildHundredBlocks` (which also serves Randomize Block Addresses) and `GeocodeCensus`, keep a reference to the original selection, run `FullWorkingSource`, then `ValidateOutputSource`, then `ConfirmWorkingSource`. On Cancel, exit quietly with no output sheet.
4. Call the confirmation only when the `source` argument was not supplied, so automated tests and internal callers are unaffected.
5. Search the whole project for other callers of `FullWorkingSource` and apply the same pattern to each.

**Tests** (`modUsabilityTests`). Assert on `ExpansionSummary`, which needs no dialog:

- A partial-column selection inside an Excel Table returns a non-empty summary containing the table's full data-row count.
- A partial-row selection in a plain contiguous range returns a summary containing the full row count.
- A selection equal to the full dataset returns an empty string.
- Existing geography assertions that pass `source` still produce identical output.

## Change 4: Repair numeric and short ZIP codes

The geocoder restores lost leading zeros and ZIP+4 hyphens, sends the repaired ZIP, and notes the repair in Review Flag. It no longer rejects a row only because the ZIP was stored as a number.

**Why.** Excel stores many ZIP columns as numbers, which drops leading zeros (02134 becomes 2134) and the ZIP+4 hyphen. `GeocodeCensusInPlace` currently marks numeric ZIPs "Invalid Input," so a numeric ZIP column can block a whole file. The `GeocodeCensus` wrapper also copies the source into text-formatted cells first, so a numeric ZIP may arrive as digit-only text. The repair must handle both forms.

**Where.** `modCensusGeocode`.

1. Add `Public Function RepairZip(ByVal raw As Variant, ByRef repaired As Boolean) As String` with these rules:
   - Numeric whole number, or text made only of digits: 3 to 5 digits pads to 5 with leading zeros; 6 to 9 digits pads to 9 and becomes "#####-####".
   - Anything else (1 to 2 digits, letters, already hyphenated text, decimals, cell errors) returns `SafeText(raw)` unchanged, so the existing ZIP format check still flags it.
   - `repaired` is True only when the returned text differs from `SafeText(raw)`.
2. In the row loop of `GeocodeCensusInPlace`, set `zip` from `RepairZip` instead of `SafeText`. Delete the "ZIP stored numerically; review leading zeros" rule.
3. Use the repaired ZIP everywhere downstream in that loop: `FullAddress`, `AddressProblem`, the de-duplication key and the CSV line sent to Census.
4. When `repaired` is True, add "ZIP restored from a number or short value; verify" to the row's note through the existing `locationNote` mechanism. Census results overwrite Review Flag, and `locationNote` is already appended after that step, so the note survives.
5. Do not change the legacy `PrepareCensus` routine; it is not a ribbon action.

**Tests** (`modCensusTests`). Unit cases for `RepairZip`:

| Input | Stored as | Expected output | Repaired |
| --- | --- | --- | --- |
| 72701 | Number | 72701 | No |
| 2134 | Number | 02134 | Yes |
| 2134 | Text | 02134 | Yes |
| 601 | Number | 00601 | Yes |
| 727011234 | Number | 72701-1234 | Yes |
| 21341234 | Number | 02134-1234 | Yes |
| 72701-1234 | Text | 72701-1234 | No |
| 12 | Text | 12 | No |
| ABCDE | Text | ABCDE | No |

Update any existing assertion that expects "ZIP stored numerically" to expect a repaired, submitted row instead. Using the fixture transport, confirm the CSV line sent for a numeric 2134 contains "02134".

## Out of scope for 1.1.0

Do not implement these in this release. They are listed so the implementer does not expand scope.

- Street suffix and directional standardization for block keys (USPS Publication 28 lookup). Planned for a later release.
- Detection or reassignment of default times such as 00:00. Identifying unknown times remains the analyst's responsibility.
- An explicit confirmation before addresses are sent to Census, and a switch to the Census geographies endpoint for tract and block group IDs.
- Code signing, moving the project to local disk, and repository location.

One manual check, with no code change unless it fails: open a Hundred\_Blocks output built from a dated source and confirm `=ISNUMBER()` returns TRUE on a date cell. If it returns FALSE, report it before release.
